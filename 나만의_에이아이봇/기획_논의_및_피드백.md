# 나만의 텔레그램·디스코드봇 만들기 — 기획 논의

작성일: 2026-08-01

## 과제명
나만의 텔레그램 * 디스코드봇 만들기

## 최종 아이디어 (재정리)

1. 사용자가 Discord로 원하는 바를 자연어 메시지로 보낸다.
   예: "내일 아침 8시에 내 discord로 내일 나의 운세, 내가 사는 동네의 날씨, 간밤에 미국-이란 전쟁 상황과 같은 국제 top news, 뉴욕 나스닥 시장의 시황과 주요 뉴스들을 보내줘"
2. 메시지에서 지정한 시각(예: 내일 아침 8시)이 되면 이게 트리거가 되어, AI Agent Node가
   - 사용자의 생년월일/생시를 이용해 운세를 보고
   - Tool을 이용해 Open-Meteo(https://open-meteo.com/)에서 동네 날씨를 가져오고
   - Tool을 이용해 NewsAPI(https://newsapi.org/)에서 요청한 뉴스(국제정세, 나스닥 시황 등)를 가져와
   - 이 내용을 합치고 요약한다
3. 요약된 브리핑을 사용자의 Discord로 메시지 전송한다.

범위: 우선 **본인 혼자 이용**하는 버전으로 진행 (다중 사용자는 추후 결과 보고 결정).

## 검토 의견

### 전체 방향: 좋은 설계
이전에 논의했던 "메시지로 요청 → 미래 시각에 발송" 시나리오와 본질적으로 같은데, n8n의 **Wait Node(특정 날짜/시각까지 대기, Resume At Specified Time)**를 활용하면 별도의 외부 저장소(Google Sheets 등)나 폴링 Cron 없이도 깔끔하게 구현 가능함. 구조:

```
Discord Trigger (사용자 메시지 수신)
  → AI Agent (메시지 파싱 → 발송시각/원하는 뉴스 주제 등 구조화)
  → Wait Node (파싱된 발송시각까지 대기)
  → AI Agent + Tools (Wait 해제 후 실행)
      - Weather Tool (Open-Meteo, 동네 고정)
      - News Tool (NewsAPI, 요청한 주제별로 여러 번 호출 가능)
      - 운세 생성 (생년월일/생시 기반, LLM 추론 — 별도 API 호출 아님)
  → 종합 요약
  → Discord Node (결과 전송)
```

이 구조면 실시간 폴링이나 별도 데이터베이스 없이도 "메시지 받은 시점과 실제 발송 시점이 다른" 요구사항을 해결할 수 있음.

### 확인이 필요한 부분

1. **생년월일/생시 출처**: 운세를 보려면 생년월일/생시가 필요한데, 이번 예시 메시지엔 포함 안 되어 있음. 본인 혼자 쓰는 거라 워크플로우에 고정값으로 넣어둘지, 아니면 사용자가 메시지 보낼 때마다 포함하게 할지 정해야 함.
2. **뉴스 주제 다중 처리**: "미국-이란 전쟁 상황", "나스닥 시황" 등 여러 주제를 요청했는데, NewsAPI는 한 번 호출에 한 가지 키워드 검색이 기본이라 AI Agent가 News Tool을 주제별로 여러 번 호출하도록 설계해야 함.
3. **자연어 시각 파싱 정확도**: "내일 아침 8시"를 실제 datetime으로 정확히 변환하려면, AI Agent 프롬프트에 "현재 날짜/시각(Asia/Seoul 기준)"을 명시적으로 넣어줘야 계산 오류가 줄어듦.
4. **1회성 vs 반복 여부**: 이 설계는 사용자가 메시지를 보낼 때마다 그 요청에 맞는 1회성 브리핑을 예약하는 구조. "매일 자동으로" 원한다면 별도 로직이 필요함 — 이번 범위에서는 1회성 요청으로 보는 게 맞는지 확인 필요.
5. **Wait Node 대기 한도**: n8n Wait Node가 하루 정도의 대기는 문제없이 지원하는 것으로 알고 있으나, 정확한 최대 대기 한도나 n8n Cloud 플랜별 제약은 제가 확실히 알지 못해서, 실제로 값을 넣어 테스트해보며 확인하는 걸 추천함.

## 트리거 및 뉴스 주제 단순화 (확정)
- 트리거를 "메시지 받을 때"에서 → **"매일 아침 8시가 되면" (Schedule Trigger)**로 변경
- 뉴스 주제를 요청마다 달라지는 자연어 대신 → **나스닥 시황 + 간밤 세계 AI 산업 주요 뉴스**로 고정

이에 따라 Discord 메시지 트리거, 자연어 시각 파싱, Wait Node가 모두 불필요해짐. 구조가 단순해짐:

```
Schedule Trigger (매일 07:55~08:00, Asia/Seoul)
  → AI Agent + Tools
      - 운세 생성 (생년월일/생시 고정값 기반, LLM 추론)
      - Weather Tool (Open-Meteo, 동네 고정)
      - News Tool (NewsAPI) — "나스닥 시황", "세계 AI 산업 뉴스" 두 번 호출
  → 종합 요약(브리핑 작성)
  → Discord Node (전송)
```

## 고정값 확정
- **생년월일/생시**: 1959년 8월 14일 (양력), 오후 11시 30분
- **동네**: 성남시 분당구
